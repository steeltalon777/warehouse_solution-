DOMAIN MODEL v2
1. Общие положения
1.1 Назначение системы

Система предназначена для учёта складских операций, управления номенклатурой, контроля остатков и разграничения доступа пользователей в мульти-складской (multi-site) среде.

1.2 Архитектурная модель

SyncServer — источник истины (бизнес-логика, доступ, состояния)

Web-клиент (Django) — пользовательский интерфейс и администрирование

API — единственный способ взаимодействия с доменной моделью

2. Пользователи и идентификация
2.1 Учетная запись пользователя (Django User)

Описание
Учетная запись создаётся и управляется в Django.

Назначение

8. Правила доступа к операциям и данным
8.1 Общий принцип доступа

В системе необходимо различать:

доступ на просмотр

доступ на изменение / выполнение операций

доступ на административное управление

Право просмотра шире, чем право выполнения операций.

Все зарегистрированные пользователи системы могут просматривать данные, доступные в основном пользовательском интерфейсе, если иное не ограничено отдельными правилами безопасности.

8.2 Просмотр данных
Правило

Все зарегистрированные пользователи могут просматривать:

склады

каталог ТМЦ

категории

остатки

операции

справочники, доступные в основном UI

Особенности

просмотр не зависит от складской привязки пользователя

просмотр доступен для всех ролей:

root

chief_storekeeper

storekeeper

observer

Исключения

административные сущности и технические разделы могут быть вынесены в отдельный контур доступа

управление пользователями и устройствами не относится к общему просмотру основного UI

8.3 Root
Полномочия

root имеет полный системный доступ без ограничений.

root может:

просматривать все данные

выполнять любые операции

подтверждать и отменять любые операции

управлять пользователями

выполнять административные действия

выполнять технические и служебные действия

Особенности

root является единственным полным системным bypass

root-полномочия вынесены в административный контур

8.4 Chief Storekeeper
Полномочия

chief_storekeeper имеет глобический бизнес-доступ ко всей складской системе, кроме системного администрирования пользователей.

chief_storekeeper может:

просматривать все склады

просматривать все операции

просматривать все остатки

просматривать и изменять справочники и номенклатуру

создавать операции на любом складе

подтверждать операции на любом складе

отменять операции в рамках бизнес-правил статусов

Ограничения

chief_storekeeper не выполняет системное управление:

пользователями

техническими устройствами

системной административной конфигурацией

8.5 Storekeeper
Полномочия на просмотр

storekeeper может просматривать:

все склады

все операции

все остатки

каталог и справочники, доступные в основном UI

Полномочия на действия

storekeeper может выполнять операции только в рамках своего рабочего склада.

Правила

источник операции для storekeeper всегда определяется его собственным складом

storekeeper не может выполнять операции от имени чужого склада как источника

storekeeper не может подтверждать операции

storekeeper не может выполнять глобическое управление справочниками, если это не разрешено отдельным UI-правом

Допустимые действия

storekeeper может:

создавать операции со своего склада

работать со своими draft-операциями, если это разрешено серверной логикой

отменять свои draft-операции, если это разрешено серверной логикой

8.6 Observer
Полномочия

observer может просматривать:

все склады

все операции

все остатки

каталог и справочники, доступные в основном UI

Ограничения

observer не может:

создавать операции

изменять операции

подтверждать операции

отменять операции

изменять справочники и номенклатуру

8.7 Создание операций
Правила

root может создавать операции на любом складе

chief_storekeeper может создавать операции на любом складе

storekeeper может создавать операции только со своего склада

observer не может создавать операции

Особенность для storekeeper

Для роли storekeeper склад-источник операции фиксируется его рабочим складом и не выбирается произвольно из списка всех складов.

8.8 Подтверждение операций
Правила

root может подтверждать любые операции

chief_storekeeper может подтверждать любые операции

storekeeper не может подтверждать операции

observer не может подтверждать операции

Особенности

подтверждение является отдельным действием

создание операции и подтверждение операции не являются одним и тем же полномочием

8.9 Отмена операций
Правила

root может отменять любые операции

chief_storekeeper может отменять любые операции в рамках бизнес-правил статуса

storekeeper может отменять только свои draft-операции, если это разрешено серверной логикой

observer не может отменять операции

8.10 Управление справочниками и системными сущностями
Справочники и номенклатура

root может управлять всеми справочниками

chief_storekeeper может управлять номенклатурой и бизнес-справочниками

storekeeper и observer не управляют номенклатурой, если иное не включено отдельным UI-правом

Пользователи и устройства

управление пользователями относится к контуру root / Django admin

управление устройствами в текущей модели не входит в полномочия chief_storekeeper

расширение полномочий по устройствам может быть введено отдельно позднее

9. Авторизация
9.1 Модель

Запрос содержит:

X-Device-Token

X-User-Token

9.2 Принцип

device token → идентификация клиента

user token → идентификация пользователя

решения принимает SyncServer

9.3 Роль Django

хранит токены

управляет учетками

вызывает API

не принимает бизнес-решения

10. Принципы проектирования

SyncServer — единственный источник истины

клиент не содержит бизнес-логики

UI может ограничивать действия, но не определяет права

система должна поддерживать замену UI без изменения домена

11. Ключевой принцип модели

Система разделяет:

UI-пользователь (Django User)

доменного пользователя (Sync User)

И использует модель доступа:

root — глобальный системный

chief_storekeeper — глобальный бизнесовый

storekeeper — scoped

observer — scoped read-only
