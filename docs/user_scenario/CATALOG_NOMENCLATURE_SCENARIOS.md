# Экраны «Каталог» и «Номенклатура»: пользовательские сценарии и acceptance-база

Документ описывает два связанных экрана:

1. **Каталог** — read-only версия номенклатуры для просмотра справочников.
2. **Номенклатура** — рабочий экран управления категориями, ТМЦ, SKU, единицами измерения и ключевыми словами.

Документ нужен для двух задач:

1. семантическая база для Playwright UI/acceptance-тестов;
2. будущий пользовательский раздел инструкции по работе со справочниками.

Каталог и Номенклатура должны использовать одну доменную модель и один источник данных. Отличие между ними не в данных, а в правах и доступных действиях. Каталог показывает, Номенклатура меняет. Простая идея, которую человечество всё равно периодически пытается испортить двумя разными экранами, тремя API и одним багом на 1613 элементов.

---

## 1. Назначение экранов

### 1.1 Каталог

Экран «Каталог» предназначен для просмотра справочников.

Пользователь может:

- смотреть дерево категорий и ТМЦ;
- искать ТМЦ по названию, SKU и ключевым словам;
- раскрывать и сворачивать категории;
- открывать карточку ТМЦ;
- смотреть единицу измерения;
- смотреть категорию;
- смотреть статус активности;
- смотреть SKU / артикул.

Пользователь не может:

- создавать категории;
- создавать ТМЦ;
- редактировать ТМЦ;
- менять единицы измерения;
- удалять;
- деактивировать;
- применять batch-изменения.

### 1.2 Номенклатура

Экран «Номенклатура» предназначен для управления справочниками.

Пользователь с правами может:

- создавать категории;
- создавать ТМЦ;
- редактировать ТМЦ;
- менять категорию;
- менять единицу измерения;
- добавлять и удалять ключевые слова;
- менять описание;
- активировать и деактивировать ТМЦ;
- создавать и редактировать единицы измерения;
- копить изменения локально;
- применять изменения batch-операцией;
- сбрасывать неподтверждённые изменения;
- экспортировать справочник.

---

## 2. Базовое доменное правило

Каталог и Номенклатура работают с одними сущностями:

- категория;
- ТМЦ;
- единица измерения;
- SKU / артикул;
- ключевые слова;
- описание;
- статус активности.

Каталог является read-only представлением Номенклатуры.

Любое изменение справочника должно проходить через SyncServer. UI может копить изменения локально, но окончательное сохранение и проверка прав выполняются сервером.

---

## 3. Роли и доступ

### Root

Может:

- видеть Каталог;
- видеть Номенклатуру;
- создавать категории;
- создавать ТМЦ;
- редактировать ТМЦ;
- деактивировать;
- удалять, если доменные правила разрешают;
- управлять единицами измерения;
- применять batch-изменения;
- экспортировать.

### Главный кладовщик

Может:

- видеть Каталог;
- видеть Номенклатуру;
- создавать и редактировать справочники;
- управлять категориями, ТМЦ и единицами измерения;
- применять batch-изменения;
- экспортировать.

### Кладовщик

Может:

- видеть Каталог;
- искать и открывать ТМЦ;
- использовать справочник при создании операций.

Не может по умолчанию:

- видеть экран Номенклатура;
- создавать категории;
- редактировать ТМЦ;
- применять batch-изменения.

### Обозреватель

Может:

- видеть Каталог;
- искать и открывать ТМЦ.

Не может:

- менять справочники;
- видеть рабочий экран Номенклатура, если он предназначен только для root/chief;
- создавать или редактировать.

---

## 4. Общие элементы экранов

Оба экрана имеют похожую структуру:

- заголовок;
- вкладки «Категории и ТМЦ» и «Единицы измерения»;
- строку поиска;
- дерево категорий и ТМЦ;
- кнопки «Раскрыть всё» и «Свернуть всё»;
- правую область с карточкой выбранного элемента.

В Каталоге правая область показывает данные только для чтения.

В Номенклатуре правая область показывает форму редактирования.

# 5. Экран «Каталог»

## 5.1 Элементы экрана

На экране отображаются:

- заголовок «Каталог»;
- описание: «Просмотр категорий, ТМЦ, единиц измерения и ключевых слов»;
- вкладка «Категории и ТМЦ»;
- вкладка «Единицы измерения»;
- поиск;
- кнопка «Раскрыть всё»;
- кнопка «Свернуть всё»;
- дерево категорий и ТМЦ;
- карточка выбранного элемента.

Карточка ТМЦ показывает:

- тип элемента: ТМЦ;
- название;
- артикул / SKU;
- единицу измерения;
- категорию;
- статус;
- ключевые слова, если есть;
- описание, если есть.

Карточка категории показывает:

- тип элемента: категория;
- название;
- родительскую категорию, если есть;
- статус;
- количество вложенных элементов, если реализовано.

Карточка единицы измерения показывает:

- название;
- символ;
- статус;
- количество связанных ТМЦ, если реализовано.

# 6. Сценарии Каталога

## CAT-UI-001: Пользователь открывает Каталог

**Дано:** пользователь вошёл в систему.

**Когда:** пользователь нажимает пункт меню «Каталог».

**Тогда:** открывается read-only экран Каталога.

Пользователь видит:

- заголовок;
- поиск;
- дерево категорий и ТМЦ;
- вкладки;
- правую область просмотра.

Для Playwright:

```text
Проверить:
- заголовок "Каталог" виден;
- поиск виден;
- дерево видно;
- вкладка "Категории и ТМЦ" видна;
- вкладка "Единицы измерения" видна;
- кнопок редактирования нет;
- нет бесконечного loader.
```

---

## CAT-UI-002: Каталог доступен всем ролям

**Дано:** пользователь имеет роль root, chief, storekeeper или observer.

**Когда:** открывает Каталог.

**Тогда:** экран доступен для просмотра.

Для всех ролей:

- дерево отображается;
- поиск работает;
- карточки открываются;
- действия редактирования недоступны.

---

## CAT-UI-003: Пользователь раскрывает категорию

**Дано:** в дереве есть категория с вложенными ТМЦ.

**Когда:** пользователь нажимает стрелку раскрытия.

**Тогда:** отображаются вложенные категории и ТМЦ.

---

## CAT-UI-004: Пользователь сворачивает категорию

**Дано:** категория раскрыта.

**Когда:** пользователь нажимает стрелку сворачивания.

**Тогда:** вложенные элементы скрываются.

---

## CAT-UI-005: Пользователь нажимает «Раскрыть всё»

**Дано:** дерево содержит несколько уровней категорий.

**Когда:** пользователь нажимает «Раскрыть всё».

**Тогда:** дерево раскрывает категории.

Если элементов слишком много, UI должен сохранять производительность и не зависать.

Рекомендуемое правило:

```text
Для больших справочников раскрытие всего дерева может выполняться порциями или с виртуализацией.
```

---

## CAT-UI-006: Пользователь нажимает «Свернуть всё»

**Дано:** дерево раскрыто.

**Когда:** пользователь нажимает «Свернуть всё».

**Тогда:** все категории сворачиваются.

---

## CAT-SEARCH-001: Поиск по названию ТМЦ

**Дано:** в каталоге есть ТМЦ «Щиток сварщика с откидным стеклом».

**Когда:** пользователь вводит `щиток сварщика`.

**Тогда:** дерево показывает найденную ТМЦ.

Поиск должен:

- работать по части названия;
- не учитывать регистр;
- игнорировать лишние пробелы;
- раскрывать путь до найденного элемента.

---

**Дано:** у ТМЦ есть SKU `63823`.

**Когда:** пользователь вводит `63823`.

**Тогда:** ТМЦ находится.

---

## CAT-SEARCH-003: Поиск по ключевому слову

**Дано:** у ТМЦ есть ключевое слово.

**Когда:** пользователь вводит ключевое слово.

**Тогда:** ТМЦ отображается в результатах.

---

## CAT-SEARCH-004: Поиск без результатов

**Дано:** пользователь ввёл строку, которой нет в справочнике.

**Когда:** поиск применён.

**Тогда:** отображается понятное пустое состояние.

Рекомендуемый текст:


**Когда:** пользователь нажимает ТМЦ.

**Тогда:** справа открывается карточка просмотра.

- SKU;

- категорию;

- описание.

## CAT-DETAIL-002: Пользователь открывает карточку категории

**Дано:** в дереве есть категория.

**Когда:** пользователь нажимает категорию.

**Тогда:** справа открывается карточка категории.

---

## CAT-DETAIL-003: Read-only режим не показывает поля ввода

**Дано:** пользователь открыл карточку ТМЦ в Каталоге.

**Тогда:** поля отображаются как текст, а не как input/select.

Проверить, что отсутствуют:

- кнопка «Добавить в изменения»;
- кнопка «Применить все»;
- кнопка «Деактивировать»;
- кнопка «Удалить»;

---

## CAT-UNITS-001: Пользователь открывает вкладку «Единицы измерения»

**Дано:** пользователь находится в Каталоге.

**Когда:** открывает вкладку «Единицы измерения».

**Тогда:** отображается список единиц измерения в read-only режиме.

# 7. Экран «Номенклатура»

## 7.1 Элементы экрана

На экране отображаются:

- заголовок «Номенклатура»;
- описание: «Категории, ТМЦ, SKU, единицы измерения и ключевые слова. Изменения копятся локально и применяются batch-ом»;
- кнопка «Экспорт»;
- кнопка «Применить все»;
- вкладка «Категории и ТМЦ»;
- вкладка «Единицы измерения»;
- поиск;
- кнопка «+ Категория»;
- кнопка «+ ТМЦ»;
- кнопки «Раскрыть всё» и «Свернуть всё»;
- дерево категорий и ТМЦ;
- счётчик элементов;
- нижняя панель локальных изменений;
- правая форма редактирования.

---

## 7.2 Принцип локального batch-редактирования

В Номенклатуре изменения могут копиться локально.

Пользователь меняет данные в форме, затем нажимает:

- «Добавить в изменения» — изменение попадает в локальный batch;
- «Сбросить» — локальная правка выбранного элемента отменяется;
- «Применить все» — все накопленные изменения отправляются на сервер.

Пока изменения не применены, SyncServer не должен считать их сохранёнными.

Если пользователь покидает экран с несохранёнными изменениями, UI должен предупредить.

Текст:

```text
Есть несохранённые изменения. Покинуть экран без применения?
```

**Дано:** пользователь root.

**Когда:** открывает экран «Номенклатура».

**Тогда:** экран доступен, действия редактирования видны.

---

## NOM-PERM-002: Главный кладовщик открывает Номенклатуру

**Дано:** пользователь chief_storekeeper.

**Когда:** открывает Номенклатуру.

**Тогда:** экран доступен, действия редактирования видны.

---

## NOM-PERM-003: Кладовщик не видит Номенклатуру в меню

**Дано:** пользователь storekeeper.

**Когда:** смотрит меню.

**Тогда:** пункт «Номенклатура» скрыт или недоступен.

Если кладовщик открыл URL напрямую, сервер или UI должны отказать.

---

## NOM-PERM-004: Observer не видит Номенклатуру в меню

**Дано:** пользователь observer.

**Тогда:** пункт «Номенклатура» скрыт или недоступен.

Для просмотра он должен использовать «Каталог».

# 9. Сценарии Номенклатуры: дерево

## NOM-TREE-001: Загрузка дерева категорий и ТМЦ

**Дано:** в справочнике есть категории и ТМЦ.

**Когда:** пользователь открывает Номенклатуру.

**Тогда:** дерево загружается полностью и показывает категории с вложенными ТМЦ.

Важно для больших справочников:

```text
Дерево должно загружать все элементы, а не только первую страницу API.
```

Если API отдаёт данные постранично, клиент должен догружать страницы до total_count.

---

## NOM-TREE-002: Счётчик элементов

**Дано:** дерево содержит элементы.

**Когда:** экран загружен.

**Тогда:** отображается количество элементов.

Счётчик должен соответствовать фактическому числу загруженных элементов.

---

## NOM-TREE-003: Выбор ТМЦ в дереве

**Дано:** пользователь нажимает ТМЦ.

**Тогда:**

- выбранная ТМЦ подсвечивается;
- справа открывается форма редактирования ТМЦ;
- заголовок формы соответствует выбранной ТМЦ.

---

## NOM-TREE-004: Выбор категории в дереве

**Дано:** пользователь нажимает категорию.

**Тогда:**

- категория подсвечивается;
- справа открывается форма категории;
- пользователь может редактировать категорию, если имеет права.

---

## NOM-TREE-005: Раскрыть всё

**Дано:** дерево содержит вложенные категории.

**Когда:** пользователь нажимает «Раскрыть всё».

**Тогда:** категории раскрываются.

Для больших деревьев действие не должно вешать браузер.

---

## NOM-TREE-006: Свернуть всё

**Дано:** дерево раскрыто.

**Когда:** пользователь нажимает «Свернуть всё».

**Тогда:** категории сворачиваются.

---

# 11. Сценарии создания категории

## NOM-CATEGORY-001: Пользователь создаёт категорию

**Дано:** пользователь имеет права.

**Когда:**

- нажимает «+ Категория»;
- вводит название;
- выбирает родительскую категорию, если нужно;
- добавляет в изменения;
- нажимает «Применить все».

**Тогда:**

- категория создаётся на сервере;
- появляется в дереве;
- доступна в формах выбора категории.

---

## NOM-CATEGORY-002: Название категории обязательно

**Когда:** пользователь пытается создать категорию без названия.

**Тогда:** система показывает ошибку:

```text
Укажите название категории.
```

---

## NOM-CATEGORY-003: Нельзя создать цикл категорий

**Дано:** есть категория А и подкатегория Б.

**Когда:** пользователь пытается сделать А дочерней категорией Б.

**Тогда:** сервер отклоняет изменение.

Текст:

```text
Категория не может быть вложена в собственную дочернюю категорию.
```

---

## NOM-CATEGORY-004: Дубль категории предупреждается

**Дано:** категория с таким названием уже есть в том же родителе.

**Когда:** пользователь создаёт такую же категорию.

**Тогда:** система показывает предупреждение или ошибку.

---

# 12. Сценарии создания ТМЦ

## NOM-ITEM-001: Пользователь создаёт ТМЦ

**Дано:** пользователь имеет права.

**Когда:**

- нажимает «+ ТМЦ»;
- вводит название;

**Тогда:**

- ТМЦ создаётся на сервере;
- появляется в дереве;
- доступна в Каталоге;
- доступна в операциях, если активна.

---

```text
Укажите название ТМЦ.
```

## NOM-ITEM-003: Единица измерения обязательна

```text
Выберите единицу измерения.
```

---

## NOM-ITEM-005: Дубль SKU предупреждается или запрещается

**Дано:** SKU уже используется другой ТМЦ.

**Когда:** пользователь пытается сохранить новую ТМЦ с тем же SKU.

**Тогда:** нужно выбрать доменное правило.

Рекомендуемое правило:

```text
SKU должен быть уникальным среди активных ТМЦ.
```

Если исторически есть дубли, UI должен предупреждать, а сервер должен соблюдать текущее доменное правило.

---

## NOM-ITEM-006: ТМЦ без категории

**Дано:** пользователь не выбрал категорию.

**Когда:** сохраняет ТМЦ.

**Тогда:** нужно выбрать правило.

Рекомендуемое правило:

```text
Категория желательна, но может быть пустой только для временных или неклассифицированных ТМЦ.
```

Если обычная ТМЦ создаётся без категории, она должна попадать в системную категорию «Без категории».

# 13. Сценарии редактирования ТМЦ

## NOM-EDIT-001: Пользователь меняет название ТМЦ

**Дано:** выбрана ТМЦ.

**Когда:** пользователь меняет название и добавляет изменение в batch.

**Тогда:** локальный счётчик изменений увеличивается.

**Когда:** пользователь нажимает «Применить все».

**Тогда:** название сохраняется на сервере и обновляется в дереве.

---

## NOM-EDIT-002: Пользователь меняет SKU

**Дано:** выбрана ТМЦ.

**Когда:** пользователь меняет SKU.

**Тогда:** после применения новый SKU отображается в карточке, Каталоге и поиске.

---

## NOM-EDIT-003: Пользователь меняет категорию

**Дано:** ТМЦ находится в категории А.

**Когда:** пользователь выбирает категорию Б и применяет изменения.

**Тогда:**

- ТМЦ перемещается в дереве;
- Каталог показывает новую категорию;
- операции с историей не ломаются.

---

## NOM-EDIT-004: Пользователь меняет единицу измерения

**Дано:** ТМЦ уже используется в операциях.

**Когда:** пользователь меняет единицу измерения.

**Тогда:** нужно выбрать доменное правило.

Рекомендуемое правило:

```text
Единицу измерения нельзя менять, если по ТМЦ уже есть операции или остатки.
```

Альтернатива:

```text
Разрешить изменение только root/chief с явной фиксацией в истории.
```

Это опасное действие, потому что «штуки» внезапно превращаются в «метры», а потом складское сознание выходит из тела.

---

## NOM-EDIT-005: Пользователь меняет описание

**Дано:** выбрана ТМЦ.

**Когда:** пользователь вводит описание и применяет изменения.

**Тогда:** описание сохраняется и отображается в Каталоге.

# 14. Сценарии ключевых слов

## NOM-TAGS-001: Пользователь добавляет ключевое слово через Enter

**Дано:** открыта форма ТМЦ.

**Когда:** пользователь вводит ключевое слово и нажимает Enter.

**Тогда:** ключевое слово добавляется как отдельный чип.

---

## NOM-TAGS-002: Запятая не разделяет ключевые слова автоматически

**Дано:** пользователь вводит значение `3,5 мм`.

**Когда:** вводит запятую.

**Тогда:** значение не должно разделиться на два ключевых слова.

Правило:

```text
Enter добавляет ключевое слово.
Запятая внутри текста допускается.
```

Это нужно, чтобы не ломать значения вроде `3,5 мм`, `М10, DIN`, `1,25 л`. Да, запятая иногда просто запятая, невероятное открытие для UI.

---

## NOM-TAGS-003: Backspace удаляет последний чип

**Дано:** поле ключевых слов пустое, но есть добавленные чипы.

**Когда:** пользователь нажимает Backspace.

**Тогда:** удаляется последний чип.

---

## NOM-TAGS-004: Максимум 20 ключевых слов

**Дано:** у ТМЦ уже 20 ключевых слов.

**Когда:** пользователь пытается добавить ещё одно.

**Тогда:** система показывает ошибку:

```text
Можно добавить не более 20 ключевых слов.
```

---

## NOM-TAGS-005: Дубликаты ключевых слов запрещены

**Дано:** ключевое слово уже добавлено.

**Когда:** пользователь пытается добавить его повторно в другом регистре.

**Тогда:** дубль не создаётся.

# 15. Сценарии активности, деактивации и удаления

**Когда:** пользователь создаёт операцию и ищет ТМЦ.

## NOM-ACTIVE-002: Деактивированная ТМЦ не доступна для новых операций

**Дано:** ТМЦ деактивирована.

**Когда:** пользователь создаёт новую операцию.

**Тогда:** ТМЦ не предлагается в поиске новых строк.

При этом исторические операции должны продолжать отображать эту ТМЦ.

## NOM-ACTIVE-003: Пользователь деактивирует ТМЦ

**Дано:** выбрана активная ТМЦ.

**Тогда:** система запрещает удаление.

```text
Нельзя удалить ТМЦ, которая используется в операциях или остатках.
```

---

## NOM-ACTIVE-005: Удаление разрешено только для неиспользованной ТМЦ

**Дано:** ТМЦ создана ошибочно и нигде не использовалась.

**Когда:** пользователь удаляет её.

**Тогда:** ТМЦ удаляется или архивируется согласно доменному правилу.

Рекомендуемое правило:

```text
Физическое удаление разрешено только для неиспользованных справочных элементов.
В остальных случаях использовать деактивацию.
```

# 17. Сценарии локального batch

## NOM-BATCH-001: Изменение попадает в локальный batch

**Дано:** пользователь изменил поле ТМЦ.

**Когда:** нажимает «Добавить в изменения».

**Тогда:**

- счётчик изменений увеличивается;
- кнопка «Применить» становится активной;
- изменение ещё не отправлено на сервер.

---

## NOM-BATCH-002: Пользователь применяет все изменения

**Дано:** в batch есть изменения.

**Когда:** пользователь нажимает «Применить все».

**Тогда:**

- изменения отправляются на сервер;
- сервер проверяет права и валидность;
- после успеха счётчик изменений становится 0;
- данные в дереве и карточке обновляются.

---

## NOM-BATCH-003: Пользователь сбрасывает локальные изменения

**Дано:** есть несохранённые изменения.

**Когда:** пользователь нажимает «Сбросить».

**Тогда:**

- изменения отменяются;
- форма возвращается к серверному состоянию;
- счётчик изменений уменьшается или становится 0.

---

## NOM-BATCH-004: Ошибка применения одного изменения

**Дано:** в batch несколько изменений.

**Когда:** сервер отклоняет одно из них.

**Тогда:** нужно выбрать правило.

Рекомендуемое правило:

```text
Batch применяется атомарно: либо все изменения сохранены, либо ни одно.
```

Если будет выбран частичный успех, UI должен явно показать, какие изменения применились, а какие нет. Но это уже мини-бухгалтерия внутри справочника, а мы вроде не садисты.

---

## NOM-BATCH-005: Пользователь уходит со страницы с несохранёнными изменениями

**Дано:** есть локальные изменения.

**Когда:** пользователь пытается перейти на другой экран.

**Тогда:** UI показывает предупреждение:

```text
Есть несохранённые изменения. Покинуть экран без применения?
```

# 19. Негативные и конкурентные сценарии

## NOM-EDGE-001: SyncServer недоступен

**Когда:** пользователь открывает экран или применяет batch.

**Тогда:** UI показывает ошибку:

```text
Сервер склада временно недоступен. Попробуйте позже.
```

Локальные изменения не должны считаться сохранёнными.

---

## NOM-EDGE-002: Два пользователя редактируют одну ТМЦ

**Дано:** пользователь А и пользователь Б открыли одну ТМЦ.

**Когда:** А применил изменения, а Б пытается применить старую версию.

**Тогда:** сервер должен отклонить конфликт или применить правило последней записи.

Рекомендуемое правило:

```text
При конфликте версий показать сообщение: "Элемент был изменён другим пользователем. Обновите данные."
```

---

## NOM-EDGE-003: Пользователь потерял права во время работы

**Дано:** пользователь открыл Номенклатуру, когда права были.

**Когда:** root изменил его роль, и пользователь нажал «Применить все».

**Тогда:** сервер отклоняет действие.

---

## NOM-EDGE-004: Большой справочник не должен терять элементы

**Дано:** справочник содержит больше 1000 элементов.

**Когда:** пользователь открывает Номенклатуру или Каталог.

**Тогда:** дерево загружает все элементы, а не только первую страницу.

Для Playwright:

```text
Подготовить справочник больше лимита одной страницы API.
Открыть Номенклатуру.
Проверить, что элемент из последней страницы доступен через поиск.
```

---

## NOM-EDGE-005: Пустые или битые данные от сервера

**Дано:** сервер вернул элемент без категории, SKU или описания.

**Когда:** UI строит дерево.

**Тогда:** экран не падает.

Рекомендуемое отображение:

- без категории → «Без категории»;
- без SKU → «SKU не указан»;
- без описания → пустое описание.

---

## NOM-EDGE-006: Двойное нажатие «Применить все»

**Дано:** пользователь нажал кнопку дважды.

**Тогда:**

- batch применяется один раз;
- кнопка блокируется на время запроса;
- дублей не создаётся.

# 22. Что нужно уточнить перед финальной реализацией

3. Можно ли менять единицу измерения у ТМЦ, которая уже участвовала в операциях.
4. Можно ли физически удалять категории, ТМЦ и единицы измерения или только деактивировать.

9. Нужен ли отдельный режим просмотра временных ТМЦ в Номенклатуре.
10. Нужна ли история изменений справочника.
11. Нужно ли согласование изменений справочника перед применением.
12. Нужна ли массовая загрузка / импорт из Excel.
13. Нужно ли экспортировать только текущий фильтр или весь справочник.
14. Как отображать элементы без категории.

# 23. Краткая инструкция для пользователя

## Каталог

Каталог нужен для просмотра справочника.

Чтобы найти ТМЦ:

1. Откройте раздел «Каталог».
2. Введите название, SKU или ключевое слово в поиск.
3. Найдите ТМЦ в дереве.
4. Нажмите на ТМЦ.
5. Справа появится карточка с данными.

В Каталоге нельзя менять данные. Если нужно исправить название, SKU, категорию или единицу измерения, это делается в разделе «Номенклатура» пользователем с правами.

## Номенклатура

Номенклатура нужна для управления справочником.

Чтобы изменить ТМЦ:

1. Откройте раздел «Номенклатура».
2. Найдите ТМЦ через дерево или поиск.
3. Выберите ТМЦ.
4. Измените нужные поля.
5. Нажмите «Добавить в изменения».
6. Проверьте счётчик изменений.
7. Нажмите «Применить все».

Пока изменения не применены, они не сохранены на сервере.

Чтобы добавить ключевое слово:

1. Введите текст в поле «Ключевые слова».
2. Нажмите Enter.
3. Ключевое слово появится как чип.
4. Чтобы удалить последнее ключевое слово, используйте Backspace в пустом поле.

Запятая не добавляет ключевое слово автоматически, чтобы можно было вводить значения вроде `3,5 мм`.

Чтобы создать ТМЦ:

1. Нажмите «+ ТМЦ».
2. Введите название.
3. Укажите SKU, если есть.
4. Выберите единицу измерения.
5. Выберите категорию.
6. Добавьте ключевые слова и описание, если нужно.
7. Добавьте изменение в batch.
8. Нажмите «Применить все».

Если кнопки редактирования недоступны, значит у пользователя нет прав на управление Номенклатурой.
