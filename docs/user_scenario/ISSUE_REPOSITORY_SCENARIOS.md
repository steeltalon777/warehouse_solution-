# Экран «Репозиторий выдачи»: пользовательские сценарии и acceptance-база

Документ описывает экран «Репозиторий выдачи» как основу для двух задач:

1. семантическая база для Playwright UI/acceptance-тестов;
2. будущий пользовательский раздел инструкции по работе с выданным имуществом.

Репозиторий выдачи — это место, где видно имущество, которое уже не лежит на складе, но ещё числится за конкретным объектом: человеком, машиной, базой, подразделением, контрагентом или прочим объектом. То есть это не «пропало», а «выдано». Разница тонкая, но для склада примерно как разница между учётом и шаманством.

---

## 1. Назначение экрана

Экран «Репозиторий выдачи» предназначен для управления выданным имуществом.

Пользователь должен быстро понять:

- какие объекты выдачи существуют;
- по каким категориям они сгруппированы;
- какое имущество закреплено за конкретным объектом;
- сколько единиц ТМЦ числится за объектом;
- когда имущество было назначено или обновлено;
- можно ли вернуть имущество на склад;
- можно ли списать имущество с объектa;
- активен ли объект выдачи;
- можно ли редактировать, деактивировать или удалить объект.

---

## 2. Базовое доменное правило

Выданное имущество — это ТМЦ, которая была снята со складского остатка операцией «Выдача» и закреплена за объектом выдачи.

Выданное имущество не должно отображаться как обычный складской остаток.

Типовой путь:

```text
операция "Выдача"
→ submit / подтверждение
→ складской остаток уменьшается
→ имущество появляется в репозитории выдачи
→ имущество закрепляется за объектом выдачи
```

Обратный путь:

```text
операция "Возврат выдачи"
→ submit / подтверждение
→ имущество снимается с объекта выдачи
→ складской остаток увеличивается
```

Списание с объекта:

```text
операция "Списание"
→ submit / подтверждение
→ имущество снимается с объекта выдачи
→ на склад не возвращается
→ в истории остаётся причина списания
```

---

## 3. Что такое объект выдачи

Объект выдачи — это сущность, за которой может числиться имущество.

Примеры объектов:

- человек;
- машина;
- база;
- подразделение;
- контрагент;
- прочий объект.

На скрине объект «Белаз A243ав» находится в категории «Машины». За ним числится ТМЦ «Датчик топливный ST3408606» в количестве `1.000`.

Объект выдачи должен иметь:

- название;
- категорию;
- тип совместимости;
- комментарий;
- внешний код, если есть;
- ключ / нормализованное имя;
- признак активности;
- дату создания;
- дату обновления.

---

## 4. Категории объектов выдачи

Категория выдачи группирует объекты в дереве.

Примеры категорий:

- Люди;
- Машины;
- Базы;
- Подразделения;
- Контрагенты;
- Прочие объекты.

Категория помогает пользователю быстро найти нужный объект и снижает шанс создать хаос уровня «Иванов, КамАЗ, база и подрядчик лежат в одной куче». Хотя люди, конечно, могут и так.

Категории могут использоваться для совместимости типов объектов.

---

## 5. Тип совместимости

Тип совместимости описывает, каким типом объекта является выбранная сущность.

Примеры:

```text
person          человек
vehicle         машина / техника
base            база
department      подразделение
contractor      контрагент
other           прочее
```

Тип совместимости нужен, чтобы операции выдачи и возврата понимали, какие объекты можно выбирать.

Пример:

- для выдачи человеку можно выбрать объект типа `person`;
- для выдачи на машину можно выбрать объект типа `vehicle`;
- для общего сценария можно разрешить любой тип.

---

## 6. Роли на экране

### Root

Может:

- видеть все категории и объекты выдачи;
- создавать категории;
- создавать объекты;
- редактировать объекты;
- деактивировать объекты;
- удалять объекты, если это разрешено доменными правилами;
- видеть назначенное имущество;
- выполнять возврат;
- выполнять списание;
- видеть историю операций.

### Главный кладовщик

Может:

- видеть все категории и объекты;
- создавать и редактировать объекты выдачи;
- создавать категории, если это разрешено бизнес-логикой;
- выполнять возврат имущества;
- выполнять списание имущества;
- контролировать выданное имущество по всем складам и объектам.

### Кладовщик

Может:

- видеть объекты выдачи;
- искать объекты;
- создавать объект выдачи при оформлении выдачи, если объект ещё не существует;
- выполнять возврат имущества, если возврат относится к его складу;
- выполнять списание с объекта, если это разрешено политикой;
- смотреть назначенное имущество.

Рекомендуемое правило:

```text
Кладовщик может создавать объект выдачи, но submit операций выдачи/возврата/списания проверяется SyncServer по складу и роли.
```

### Обозреватель

Может:

- видеть дерево объектов;
- открывать карточку объекта;
- смотреть назначенное имущество.

Не может:

- создавать категории;
- создавать объекты;
- редактировать объекты;
- деактивировать;
- удалять;
- возвращать имущество;
- списывать имущество.

---

## 7. Элементы экрана

Экран состоит из двух основных областей.

### Левая область

Левая область содержит:

- строку поиска;
- кнопку «+ Объект выдачи»;
- кнопку «+ Категория выдачи»;
- дерево категорий и объектов;
- кнопки управления деревом, если реализованы.

В дереве отображаются:

- категории;
- вложенные объекты;
- активный выбранный объект.

### Правая область

Правая область содержит карточку выбранного объекта:

- название объекта;
- подпись «Объект выдачи»;
- кнопки «Редактировать», «Деактивировать», «Удалить»;
- блок «Параметры объекта»;
- блок «Назначенное имущество».

---

## 8. Поля карточки объекта

В карточке объекта отображаются:

- наименование;
- комментарий;
- категория;
- тип совместимости;
- внешний код;
- признак активности;
- ключ;
- дата создания;
- дата обновления.

### Наименование

Обязательное поле. Используется для поиска и отображения.

### Комментарий

Дополнительная информация об объекте. Например водитель, назначение машины, подразделение или пояснение.

### Категория

Обязательное поле. Определяет место объекта в дереве.

### Тип совместимости

Определяет, в каких операциях объект может использоваться.

### Код

Внешний код объекта, если он есть. Например госномер, инвентарный номер, табельный номер или код контрагента.

### Активен

Если объект активен, его можно использовать в новых операциях выдачи.

Если объект деактивирован, он остаётся в истории, но не должен предлагаться для новых выдач.

### Ключ

Нормализованный ключ объекта. Нужен для поиска дублей.

Пример:

```text
Белаз A243ав → белаз a243ав
Кузьмин Максим Владимирович → кузьмин максим владимирович
```

---

## 9. Блок «Назначенное имущество»

Блок показывает ТМЦ, которая сейчас числится за выбранным объектом.

Колонки:

- №;
- наименование ТМЦ;
- артикул / SKU;
- количество;
- обновлено;
- действия.

Доступные действия:

- «Возврат»;
- «Списание».

---

# 10. Базовые сценарии пользователя

## ISSUE-REPO-001: Пользователь открывает репозиторий выдачи

**Дано:** пользователь вошёл в систему.

**Когда:** пользователь нажимает пункт меню «Репозиторий выдачи».

**Тогда:** открывается экран репозитория выдачи.

Пользователь видит:

- заголовок;
- описание;
- поиск;
- дерево категорий и объектов;
- карточку выбранного объекта или пустое состояние;
- назначенное имущество, если объект выбран.

Для Playwright:

```text
Проверить:
- заголовок "Репозиторий выдачи" виден;
- поиск виден;
- кнопка "+ Объект выдачи" видна ролям с правами;
- дерево категорий видно;
- правая область карточки видна;
- нет бесконечного loader.
```

---

## ISSUE-REPO-002: Нет объектов выдачи

**Дано:** в системе нет объектов выдачи.

**Когда:** пользователь открывает экран.

**Тогда:** отображается пустое состояние.

Рекомендуемый текст:

```text
Объекты выдачи не найдены.
Создайте объект выдачи или оформите операцию выдачи с новым объектом.
```

Для observer текст должен быть другим:

```text
Объекты выдачи не найдены.
```

Потому что observer не может создавать объекты, а показывать ему призыв «создайте» — это UI-издевательство.

---

## ISSUE-REPO-003: Пользователь выбирает объект в дереве

**Дано:** в дереве есть объект выдачи.

**Когда:** пользователь нажимает объект.

**Тогда:** справа открывается карточка объекта.

Ожидаемо:

- выбранный объект подсвечен;
- заголовок карточки соответствует объекту;
- поля объекта заполнены;
- блок назначенного имущества обновился.

---

## ISSUE-REPO-004: Пользователь раскрывает и сворачивает категории

**Дано:** дерево содержит категории и объекты.

**Когда:** пользователь раскрывает категорию.

**Тогда:** отображаются вложенные объекты.

**Когда:** пользователь сворачивает категорию.

**Тогда:** вложенные объекты скрываются.

---

# 11. Сценарии поиска

## ISSUE-SEARCH-001: Поиск объекта по названию

**Дано:** есть объект «Белаз A243ав».

**Когда:** пользователь вводит `белаз` в поиск.

**Тогда:** дерево показывает найденный объект или раскрывает категорию, где он находится.

Поиск должен:

- работать по части названия;
- не учитывать регистр;
- игнорировать лишние пробелы.

---

## ISSUE-SEARCH-002: Поиск объекта по категории

**Дано:** есть категория «Машины».

**Когда:** пользователь вводит `машины`.

**Тогда:** отображается категория и её объекты.

---

## ISSUE-SEARCH-003: Поиск объекта по комментарию

**Дано:** у объекта есть комментарий.

**Когда:** пользователь вводит фрагмент комментария.

**Тогда:** объект находится.

---

## ISSUE-SEARCH-004: Поиск не должен создавать дублей из-за орфографии

**Дано:** пользователь ищет человека или машину с разными вариантами написания.

**Когда:** вводит похожее название.

**Тогда:** система должна показывать существующие похожие объекты перед созданием нового.

Примеры дублей:

```text
Иванов Иван Иванович
Иванов И.И.
иванов иван
Иванов
```

Для MVP достаточно показывать поиск по нормализованному ключу. Более умное сравнение можно добавить позже. Да, пользователи всё равно найдут способ написать «Белаз» восемью способами. Это их древнее ремесло.

---

# 12. Сценарии создания категории

## ISSUE-CATEGORY-001: Пользователь создаёт категорию выдачи

**Дано:** пользователь имеет право создавать категории.

**Когда:** нажимает «+ Категория выдачи», вводит название и сохраняет.

**Тогда:**

- категория появляется в дереве;
- её можно выбрать;
- в неё можно добавлять объекты.

---

## ISSUE-CATEGORY-002: Категория требует название

**Когда:** пользователь пытается сохранить категорию без названия.

**Тогда:** система показывает ошибку:

```text
Укажите название категории.
```

---

## ISSUE-CATEGORY-003: Нельзя создать дубль категории

**Дано:** категория «Машины» уже существует.

**Когда:** пользователь пытается создать ещё одну категорию «машины».

**Тогда:** система показывает ошибку или предлагает использовать существующую категорию.

---

## ISSUE-CATEGORY-004: Observer не видит кнопку создания категории

**Дано:** пользователь с ролью observer открыл экран.

**Тогда:** кнопка «+ Категория выдачи» скрыта или недоступна.

---

# 13. Сценарии создания объекта выдачи

## ISSUE-OBJECT-001: Пользователь создаёт объект выдачи

**Дано:** пользователь имеет право создавать объекты.

**Когда:**

- нажимает «+ Объект выдачи»;
- вводит наименование;
- выбирает категорию;
- выбирает тип совместимости;
- при необходимости вводит код и комментарий;
- сохраняет.

**Тогда:**

- объект появляется в дереве;
- объект активен по умолчанию;
- объект можно выбрать в операциях выдачи;
- карточка объекта открывается справа.

---

## ISSUE-OBJECT-002: Наименование объекта обязательно

**Когда:** пользователь пытается сохранить объект без наименования.

**Тогда:** система показывает ошибку:

```text
Укажите наименование объекта.
```

---

## ISSUE-OBJECT-003: Категория объекта обязательна

**Когда:** пользователь не выбрал категорию.

**Тогда:** система показывает ошибку:

```text
Выберите категорию объекта.
```

---

## ISSUE-OBJECT-004: Тип совместимости обязателен

**Когда:** пользователь не выбрал тип совместимости.

**Тогда:** система показывает ошибку:

```text
Выберите тип объекта.
```

---

## ISSUE-OBJECT-005: Создание объекта с внешним кодом

**Дано:** машина имеет госномер или внешний код.

**Когда:** пользователь вводит код.

**Тогда:** код сохраняется и отображается в карточке.

Код может использоваться для поиска.

---

## ISSUE-OBJECT-006: Предупреждение о похожем объекте

**Дано:** похожий объект уже существует.

**Когда:** пользователь пытается создать новый объект с похожим названием или кодом.

**Тогда:** система показывает предупреждение:

```text
Похожий объект уже существует. Проверьте, не создаёте ли вы дубль.
```

Рекомендуемое поведение:

- не запрещать создание жёстко на первом этапе;
- но показывать предупреждение;
- если совпадает внешний код, запрещать создание дубля.

---

# 14. Сценарии редактирования объекта

## ISSUE-EDIT-001: Пользователь открывает редактирование объекта

**Дано:** объект выбран.

**Когда:** пользователь нажимает «Редактировать».

**Тогда:** поля карточки становятся доступными для изменения или открывается форма редактирования.

---

## ISSUE-EDIT-002: Пользователь меняет комментарий

**Дано:** объект выбран.

**Когда:** пользователь меняет комментарий и сохраняет.

**Тогда:** комментарий обновляется, дата обновления меняется.

---

## ISSUE-EDIT-003: Пользователь меняет категорию объекта

**Дано:** объект находится в категории «Машины».

**Когда:** пользователь меняет категорию на другую.

**Тогда:**

- объект перемещается в дереве;
- назначенное имущество не теряется;
- история объекта сохраняется.

---

## ISSUE-EDIT-004: Пользователь меняет тип совместимости

**Дано:** объект используется в истории выдачи.

**Когда:** пользователь меняет тип совместимости.

**Тогда:** нужно выбрать доменное правило.

Рекомендуемое правило:

```text
Тип совместимости можно менять только если это не ломает историю и текущие назначения.
```

Для MVP можно разрешить изменение только root/chief.

---

## ISSUE-EDIT-005: Observer не может редактировать объект

**Дано:** observer открыл карточку объекта.

**Тогда:** кнопка «Редактировать» скрыта или disabled.

Прямой запрос на изменение должен быть отклонён сервером.

---

# 15. Сценарии деактивации и удаления объекта

## ISSUE-DEACTIVATE-001: Пользователь деактивирует объект без назначенного имущества

**Дано:** объект активен и за ним ничего не числится.

**Когда:** пользователь нажимает «Деактивировать».

**Тогда:**

- объект становится неактивным;
- объект остаётся в истории;
- объект не предлагается для новых выдач.

---

## ISSUE-DEACTIVATE-002: Пользователь деактивирует объект с назначенным имуществом

**Дано:** за объектом числится имущество.

**Когда:** пользователь нажимает «Деактивировать».

**Тогда:** нужно выбрать доменное правило.

Рекомендуемое правило:

```text
Деактивация объекта с назначенным имуществом запрещена.
Сначала нужно вернуть или списать всё назначенное имущество.
```

Текст ошибки:

```text
Нельзя деактивировать объект, пока за ним числится имущество.
```

---

## ISSUE-DELETE-001: Пользователь удаляет объект без истории

**Дано:** объект был создан ошибочно и не участвовал в операциях.

**Когда:** пользователь нажимает «Удалить».

**Тогда:** объект удаляется или архивируется.

Рекомендуемое правило:

```text
Физическое удаление разрешено только если объект не участвовал в операциях и за ним нет имущества.
```

---

## ISSUE-DELETE-002: Нельзя удалить объект с историей

**Дано:** объект участвовал в операциях выдачи или возврата.

**Когда:** пользователь пытается удалить объект.

**Тогда:** система запрещает удаление.

Текст:

```text
Нельзя удалить объект, который используется в истории операций.
```

Лучше использовать деактивацию вместо удаления. Удаление истории — это когда база данных начинает делать вид, что прошлого не было. Люди так умеют, но системе не надо.

**Когда:** пользователь открывает карточку.

**Тогда:** блок «Назначенное имущество» показывает пустое состояние.

```text
За объектом сейчас не числится имущество.
```

## ISSUE-ASSET-002: Объект с назначенным имуществом

**Дано:** за объектом числится ТМЦ.

**Когда:** пользователь открывает карточку.

**Тогда:** в таблице «Назначенное имущество» отображаются строки.

Для каждой строки видны:

- номер;
- наименование ТМЦ;
- артикул;
- количество;
- дата обновления;
- действия «Возврат» и «Списание».

**Дано:**

- на складе есть ТМЦ;
- создана и подтверждена операция «Выдача» на объект.

**Тогда:**


- история фиксирует частичный возврат.

## ISSUE-RETURN-004: Нельзя вернуть больше, чем числится

**Когда:** пользователь пытается вернуть 2.

## ISSUE-RETURN-005: Возврат требует склад назначения

**Когда:** пользователь пытается подтвердить возврат без склада.

**Тогда:** система показывает ошибку:

```text

```

---

## ISSUE-RETURN-006: Возврат через черновик операции

Если возврат создаётся как операция, рекомендуемый путь такой:

```text
нажать "Возврат"
→ создать черновик операции "Возврат выдачи"
→ пользователь проверяет строки
→ пользователь с правами делает submit
→ имущество снимается с объекта
→ остаток склада увеличивается
```

Это более правильно архитектурно, потому что все движения имущества идут через операции. И да, это чуть больше кликов. Зато потом не надо проводить археологию в базе.

# 25. Что нужно уточнить перед финальной реализацией

Перед превращением документа в строгие автотесты нужно закрепить правила:

1. Может ли кладовщик создавать категории выдачи или только объекты.
2. Может ли кладовщик редактировать объект после создания.
3. Можно ли деактивировать объект, если за ним числится имущество.
4. Можно ли физически удалить объект или только архивировать.
5. Возврат и списание выполняются напрямую с экрана или через создание черновика операции.
6. Кто может списывать имущество с объекта: кладовщик своего склада или только chief/root.
7. Как определяется склад возврата при возврате выдачи.
8. Суммируются ли одинаковые ТМЦ на одном объекте в одну строку.
9. Нужна ли история назначений прямо на карточке объекта.
10. Нужны ли вложенные категории объектов выдачи.
11. Как обрабатывать похожие объекты и дубли.
12. Нужны ли вложения: фото, акт, комментарии, документы.
13. Должны ли деактивированные объекты отображаться в дереве по умолчанию.
14. Может ли объект выдачи быть связан с внешним справочником техники, сотрудников или контрагентов.
15. Должен ли объект выдачи иметь ответственного пользователя.

# 26. Краткая инструкция для пользователя

Экран «Репозиторий выдачи» показывает имущество, которое было выдано и сейчас числится за человеком, машиной, базой, подразделением или другим объектом.

Чтобы посмотреть выданное имущество:

1. Откройте раздел «Репозиторий выдачи».
2. Найдите объект через поиск или дерево категорий.
3. Выберите объект.
4. Справа откроется карточка объекта.
5. В блоке «Назначенное имущество» будет видно, что за ним числится.

Чтобы вернуть имущество:

1. Найдите объект.
2. В таблице «Назначенное имущество» нажмите «Возврат».
3. Укажите склад возврата.
4. Укажите количество.
5. Подтвердите действие или создайте операцию возврата, если система работает через черновики.
6. После подтверждения имущество вернётся на склад.

Чтобы списать имущество:

1. Найдите объект.
2. В таблице «Назначенное имущество» нажмите «Списание».
3. Укажите количество.
