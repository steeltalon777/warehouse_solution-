# Scope: ручное обновление остатков в окне операций (Angular)

**Статус:** ✅ реализован (2026-08-07) — `docs/TZ-OPERATION_MODAL_BALANCES_MANUAL_REFRESH.md` (реализация + unit/component + e2e + regression, все прогоны зелёные)
**Дата:** 2026-07-14
**Решение:** пользователь (кладовщик + разработчик)
**Источник проблемы:** неявное и непрозрачное поведение автосинка остатков в `OperationCreateModalComponent`

---

## Проблема

В Angular-форме создания/редактирования операции остатки ТМЦ сейчас подтягиваются автоматически:

1. **Эффект на смену склада** (`operation-create-modal.component.ts:963-1002`) — при любом изменении `relevantSiteId()` дёргается `loadBalances(siteId)` + `refreshSourceQuantities()` по всем строкам черновика.
2. **Перед submit/save** (`refreshBeforePersist()` в `operation-create-modal.component.ts:1049-1062`) — принудительный рефреш остатков всех строк.

Кладовщик наблюдает «иногда актуально, иногда нет» — автосинк срабатывает в непредсказуемые моменты, есть гонки (`balanceRefreshSeq` уже пытались разрулить, но поведение всё равно мутное). Хочется явного ручного контроля: остаток обновляется тогда, когда пользователь сам нажал кнопку или когда он только что выбрал ТМЦ / сменил склад.

Дополнительно — в выпадашке поиска (`ItemCacheSearchComponent:63-65`) показывается «на складе: X» через поле `source_site_qty`. Это лишний обогащающий HTTP-запрос на каждую букву поиска, и эта цифра часто расходится с реальностью (тот же баг).

---

## In Scope

1. **Убрать глобальный автосинк остатков при смене склада и перед submit** в `OperationCreateModalComponent`.
   - Удалить `effect()` на `relevantSiteId()` (текущие строки 963-1002).
   - Удалить `refreshBeforePersist()` и его вызовы из `save()` / `submit()` (строки 1049-1062).
   - Удалить сигналы/состояние автосинка (`isBalanceRefreshing`, `balanceRefreshSeq`), если после правки они больше нигде не нужны.

2. **Оставить точечный автозапрос при добавлении/выборе ТМЦ** в строку:
   - `onItemSelected(localId, item)` (1166-1187) — выбор существующей ТМЦ.
   - `onNewItemSelected(item)` (1189-1216) — добавление новой ТМЦ в черновик.
   - В обоих случаях — ровно один вызов `service.getBalanceForItem(itemId, siteId)`.

3. **Оставить автозапрос остатков при смене склада**, но без гонок:
   - При изменении `relevantSiteId()` — один раз подтянуть остатки всех строк нового склада через тот же механизм, что и сейчас, но убрать `refreshBeforePersist` и ручную «вечную» логику.
   - Конкурентность запросов не должна порождать устаревшие данные — оставить актуальный `balanceRefreshSeq` (или эквивалент) для одной этой точки.

4. **Добавить кнопку «Обновить всё»** в шапку таблицы строк:
   - В `OperationLinesTableComponent` — иконка/кнопка рядом с заголовком «Имеется».
   - При клике — эмитится событие `refreshAllBalances` родителю.
   - В родительском `OperationCreateModalComponent` обрабатывается параллельным `forkJoin` (или `Promise.all` через RxJS-to-Promise конвертацию) `loadBalances`-per-row.
   - На время запроса — кнопка `disabled` + спиннер, после — обновляются все строки разом.

5. **Скрыть остаток в выпадашке поиска** (`ItemCacheSearchComponent`):
   - Удалить `<span class="option-stock">на складе: {{ item.source_site_qty }}</span>` (строки 63-65) и связанные стили.
   - В `CatalogSearchService.searchItemsOnce` / `performItemSearch` для этого потребителя — передавать `include_balance=false`, чтобы `CatalogCachedItemSearchView` не делал обогащение через `BalancesAPI.list_balances` на каждую букву поиска (экономия HTTP-запросов).

6. **Не трогать legacy Django SSR форму** (`templates/operations/form.html`, `static/js/operations_create.js`) — автосинка там нет, остатки в выпадашке не показываются, минимально-обратимая правка только в Angular.

## Out of Scope

- Рефакторинг `OperationCreateModalComponent` (1282 строки) — точечные правки, без разбиения на подкомпоненты.
- Изменение BFF/SyncServer контрактов — используем существующий `GET /bff/api/v1/balances?site_id=X&item_id=Y`.
- Показ timestamp последнего обновления остатков.
- Подсветка «устаревших» остатков / визуальная индикация.
- Bulk-эндпоинт в BFF (`POST /bff/api/v1/operations/refresh-balances`) — в этой итерации per-row параллельные запросы; bulk — оптимизация на будущее.
- Изменение `Functional and WorkLogik.md` — требование «указание количества на выбранном складе» (п. II/5.0) сохраняется, просто источник становится явным (ручной + точечный авто при добавлении).
- Локализация / i18n новых строк UI.

## Success Criteria

1. При смене склада в форме операции остатки строк обновляются автоматически один раз (без гонок и без постоянного перезапроса).
2. Кнопка «Обновить всё» в шапке таблицы строк обновляет остатки всех строк параллельно; UI показывает спиннер и disabled на время запроса.
3. При добавлении новой ТМЦ в строку через поиск остаток подтягивается ровно один раз.
4. В выпадашке поиска ТМЦ поле «на складе: X» не отображается; HTTP-запрос на обогащение остатками не выполняется.
5. Submit операции не вызывает фонового обновления остатков — submit работает на текущих значениях формы.
6. Тесты проходят, Angular build проходит, smoke на стенде подтверждает поведение.

## Допущения

| Допущение | Статус | Валидация |
|---|---|---|
| Backend `GET /bff/api/v1/balances?site_id=X&item_id=Y` отдаёт остаток конкретной ТМЦ на конкретном складе за 1 запрос | Валидировано | `Warehouse_web/apps/sync_client/balances_api.py:20-39` и `Warehouse_web/apps/bff_api/balances_views.py:19-31` |
| `OperationLinesTableComponent` уже умеет принимать состояние `isRefreshing` от родителя и показывать «…» | Валидировано | строки 98-110 (рендер `availableQuantity` / `…` / `—`) |
| В BFF лимит на размер запросов по `item_id` не упрётся при типичных черновиках (до 50 строк) | Разумное | SyncServer не накладывает жёстких лимитов на `item_id`-фильтр; при >50 строках нужен будет bulk, отложено |
| `balanceRefreshSeq` (или эквивалент) достаточно для устранения гонок в одной оставшейся точке (смена склада) | Разумное | уже используется в текущем коде для этой же цели |
| Параллельные запросы per-row (forkJoin) не превысят лимиты на стороне SyncServer / Django | Разумное | SyncServer `/balances` не имеет явного concurrency-лимита; при проблемах — bulk-эндпоинт |
| `include_balance=false` для `ItemCacheSearchComponent` не сломает другие потребители поля `source_site_qty` | Валидировано | `ItemCacheSearchComponent` — единственный потребитель внутри формы операций; в обычном каталоге поле используется отдельно и не зависит от этой правки |

## Альтернативы

| Подход | Вердикт | Причина |
|---|---|---|
| Ничего не менять | Отклонено | Автосинк непрозрачен, кладовщик не понимает, когда данные актуальны |
| Только per-row кнопка в каждой строке (без общей) | Отклонено | UX хуже: если 30 строк, нужно 30 кликов; пользователь выбрал одну общую кнопку |
| Bulk-эндпоинт в BFF `POST /bff/api/v1/operations/refresh-balances` | Отложено | Архитектурно чище, но требует новой ручки + тестов; для первой итерации достаточно per-row параллельных |
| Полностью убрать все остатки из формы | Отклонено | Нарушает п. II/5.0 `Functional and WorkLogik.md` — «указание количества на выбранном складе» обязательно |
| Убрать остатки и из строк, и из выпадашки | Отклонено | То же — нарушает ФЗ, и лишает кладовщика контроля наличия перед подтверждением |
| Сделать bulk в Django SSR тоже | Отложено | Django SSR — fallback без автосинка; активный фронт — Angular |

## Выбранный подход

Снимаем глобальный автосинк (`effect` + `refreshBeforePersist`), оставляем точечный автозапрос в трёх местах (добавление ТМЦ, выбор существующей ТМЦ, смена склада), добавляем одну общую кнопку «Обновить всё» в шапку таблицы строк с параллельными per-row запросами и спиннером, скрываем остаток в выпадашке поиска и отключаем `include_balance` для этого потребителя. Backend не трогаем.

### Требуемые unit/component тесты

1. `OperationCreateModalComponent`:
   - При смене `relevantSiteId` остатки подтягиваются один раз (без `refreshBeforePersist`).
   - При добавлении новой ТМЦ — один вызов `getBalanceForItem`.
   - При submit — `loadBalances` НЕ вызывается.
2. `OperationLinesTableComponent`:
   - Кнопка «Обновить всё» рендерится.
   - При клике — эмитится `refreshAllBalances`.
   - При `isRefreshing=true` — кнопка `disabled` и со спиннером.
3. `ItemCacheSearchComponent`:
   - Span «на складе: X» не отображается.
   - В запросе уходит `include_balance=false` (проверка через spy на `CatalogSearchService`).
