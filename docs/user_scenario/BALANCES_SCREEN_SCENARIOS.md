# Экран «Остатки»: пользовательские сценарии и acceptance-база

Документ описывает экран «Остатки» как основу для двух задач:

1. семантическая база для Playwright UI/acceptance-тестов;
2. будущий пользовательский раздел инструкции по просмотру текущих складских остатков.

Экран «Остатки» не предназначен для ручного изменения количества ТМЦ. Остатки должны изменяться только через складские операции: приход, расход, перемещение, списание, выдачу, возврат выдачи и корректировку. Если кто-то захочет «просто поправить цифру в таблице», ему надо мягко, но уверенно объяснить, что это путь в бухгалтерский хоррор.

---

## 1. Назначение экрана

Экран «Остатки» показывает текущее количество ТМЦ по доступным складам.

Пользователь должен быстро понять:

- какая ТМЦ есть в системе;
- на каком складе она числится;
- сколько её сейчас;
- когда остаток был обновлён;
- как найти нужную ТМЦ по названию, SKU, категории или ID;
- как отфильтровать только положительные остатки;
- как посмотреть остатки по конкретному складу.

---

## 2. Базовое доменное правило

Остаток — это результат проведённых складских операций.

На экране «Остатки» нельзя напрямую редактировать количество.

Правильный способ изменить остаток:

- приход увеличивает остаток;
- расход уменьшает остаток;
- перемещение меняет остатки складов по правилам приёмки;
- списание уменьшает остаток;
- выдача снимает ТМЦ со склада и переносит в репозиторий выдачи;
- возврат выдачи возвращает ТМЦ на склад;
- корректировка создаёт отдельную операцию корректировки.

Экран «Остатки» является экраном просмотра, поиска, фильтрации и контроля, а не экраном ручного редактирования.

---

## 3. Роли на экране остатков

### Root

Может:

- видеть остатки по всем складам;
- фильтровать по любому складу;
- открывать сводку;
- переходить к связанным операциям, если такой переход реализован.

### Главный кладовщик

Может:

- видеть остатки по всем складам;
- фильтровать по любому складу;
- открывать сводку;
- использовать остатки для контроля операций и приёмки.

### Кладовщик

Может:

- видеть остатки;
- фильтровать по складам;
- использовать остатки для создания операций;
- видеть количество на своём складе как основной рабочий сценарий.

Если доменная политика ограничивает кладовщика только своими складами, UI должен показывать только доступные склады. Если общая политика просмотра шире, кладовщик может видеть все остатки, но проводить операции только по своим складам.

### Обозреватель

Может:

- видеть остатки;
- искать и фильтровать;
- открывать сводку, если это разрешено.

Не может:

- создавать операции из остатков, если кнопки быстрых действий будут добавлены;
- изменять количество;
- делать корректировки.

---

## 4. Элементы экрана

На экране отображаются:

- заголовок «Остатки»;
- описание: «Текущие остатки ТМЦ по доступным складам»;
- кнопка «Сводка»;
- поле поиска;
- поле «ID ТМЦ»;
- фильтр «Склад»;
- выбор количества строк на странице;
- чекбокс «Только положительные»;
- кнопка «Применить»;
- кнопка «Сбросить», если реализована;
- таблица остатков.

В таблице отображаются колонки:

- ТМЦ;
- склад;
- количество;
- обновлено.

Рекомендуемые дополнительные колонки на будущее:

- SKU;
- категория;
- единица измерения;
- резерв / в пути, если такие состояния появятся;
- действия: открыть карточку ТМЦ, показать историю операций.

---

## 5. Смысл колонок

### ТМЦ

Название товарно-материальной ценности. Пользователь должен узнавать предмет по человеческому названию, а не по внутреннему ID, потому что нормальные люди не мыслят UUID-ами. Пока что.

### Склад

Склад или участок, на котором числится остаток.

### Количество

Текущее количество ТМЦ на выбранном складе.

Количество может быть:

- `0` — ТМЦ есть в справочнике, но на складе её сейчас нет;
- больше `0` — ТМЦ есть в наличии;
- меньше `0` — нежелательное состояние, которое должно считаться ошибкой данных или особым доменным случаем, если такое разрешено.

Рекомендуемое правило:

```text
Отрицательные остатки запрещены.
```

Если отрицательные остатки всё же возможны временно, это должно быть отдельно описано в домене.

### Обновлено

Дата и время последнего изменения остатка.

Это поле помогает понять, когда последний раз остаток менялся через операцию.

---

# 6. Базовые сценарии пользователя

## BAL-SCREEN-001: Пользователь открывает экран «Остатки»

**Дано:** пользователь вошёл в систему.

**Когда:** пользователь нажимает пункт меню «Остатки».

**Тогда:** открывается экран текущих остатков.

Пользователь видит:

- заголовок;
- фильтры;
- таблицу;
- пагинацию;
- кнопку «Сводка».

Для Playwright:

```text
Проверить:
- заголовок "Остатки" виден;
- поле поиска видно;
- фильтр склада виден;
- таблица остатков видна;
- пагинация видна;
- нет бесконечного loader;
- нет ошибки загрузки.
```

---

## BAL-SCREEN-002: Список остатков пуст

**Дано:** в системе нет остатков или фильтры ничего не нашли.

**Когда:** пользователь открывает экран или применяет фильтры.

**Тогда:** отображается понятное пустое состояние.

Рекомендуемый текст:

```text
Остатки не найдены.
Попробуйте изменить фильтры или проверить выбранный склад.
```

Для Playwright:

```text
Проверить:
- empty-state отображается;
- таблица не выглядит сломанной;
- пагинация не показывает некорректные значения;
- нет ошибки 500/403.
```

---

## BAL-SCREEN-003: Пользователь ищет ТМЦ по названию

**Дано:** в остатках есть ТМЦ «Мультиметр».

**Когда:** пользователь вводит `мультиметр` в поле поиска и нажимает «Применить».

**Тогда:** таблица показывает строки, где название ТМЦ содержит этот текст.

Требования к поиску:

- поиск работает без учёта регистра;
- пробелы в начале и конце игнорируются;
- частичное совпадение работает.

---

## BAL-SCREEN-004: Пользователь ищет ТМЦ по SKU

**Дано:** у ТМЦ есть SKU или артикул.

**Когда:** пользователь вводит SKU в поле поиска.

**Тогда:** таблица показывает соответствующую ТМЦ.

Если SKU не отображается в таблице, поиск всё равно должен работать, если поле доступно в данных.

---

## BAL-SCREEN-005: Пользователь ищет ТМЦ по категории

**Дано:** ТМЦ относится к категории, например «Инструмент».

**Когда:** пользователь вводит название категории в поиск.

**Тогда:** таблица показывает ТМЦ из этой категории.

---

## BAL-SCREEN-006: Пользователь ищет по ID ТМЦ

**Дано:** пользователь знает внутренний ID ТМЦ.

**Когда:** вводит ID в поле «ID ТМЦ» и нажимает «Применить».

**Тогда:** таблица показывает остатки только по этой ТМЦ.

Проверки:

- числовой ID работает;
- пустой ID игнорируется;
- несуществующий ID показывает пустое состояние;
- некорректный ID показывает валидационную ошибку.

Рекомендуемый текст ошибки:

```text
ID ТМЦ должен быть числом.
```

---

## BAL-SCREEN-007: Пользователь фильтрует остатки по складу

**Дано:** остатки есть на нескольких складах.

**Когда:** пользователь выбирает склад и нажимает «Применить».

**Тогда:** таблица показывает остатки только по выбранному складу.

Для Playwright:

```text
Выбрать склад "Угдан".
Нажать "Применить".
Проверить, что в колонке "Склад" отображается только "Угдан".
```

---

## BAL-SCREEN-008: Пользователь включает «Только положительные»

**Дано:** в таблице есть ТМЦ с количеством `0` и количеством больше `0`.

**Когда:** пользователь включает чекбокс «Только положительные» и нажимает «Применить».

**Тогда:** таблица показывает только строки, где количество больше нуля.

Для Playwright:

```text
Включить "Только положительные".
Нажать "Применить".
Проверить, что в колонке "Количество" нет значений 0.
```

---

## BAL-SCREEN-009: Пользователь сбрасывает фильтры

**Дано:** заполнены поиск, ID ТМЦ, склад, чекбокс «Только положительные».

**Когда:** пользователь нажимает «Сбросить».

**Тогда:**

- поиск очищается;
- ID ТМЦ очищается;
- склад возвращается к значению по умолчанию;
- чекбокс «Только положительные» снимается;
- таблица обновляется.

Если кнопки сброса нет, сценарий должен быть реализован при добавлении кнопки, потому что очищать фильтры руками — это маленькая, но регулярная пытка.

---

# 7. Сценарии просмотра данных

## BAL-DATA-001: Отображение нулевых остатков

**Дано:** у ТМЦ на складе количество `0`.

**Когда:** пользователь открывает экран без фильтра «Только положительные».

**Тогда:** строка отображается.

Количество `0` должно быть визуально понятно, но не должно считаться ошибкой.

---

## BAL-DATA-002: Отображение положительных остатков

**Дано:** у ТМЦ есть положительный остаток.

**Когда:** пользователь открывает экран.

**Тогда:** количество отображается корректно.

Рекомендуемое поведение:

- малые положительные остатки можно подсвечивать предупреждением, если будет введён минимальный порог;
- обычные положительные остатки отображаются стандартно;
- нули можно отображать отдельно или приглушённо.

---

## BAL-DATA-003: Отображение даты обновления

**Дано:** остаток был изменён операцией.

**Когда:** пользователь смотрит колонку «Обновлено».

**Тогда:** видит дату и время последнего изменения.

Рекомендация для UI:

- показывать дату в человекочитаемом формате;
- ISO-строку можно оставить для технического режима, но обычному пользователю лучше формат `ДД.ММ.ГГГГ ЧЧ:ММ`.

---

## BAL-DATA-004: Остаток после прихода

**Дано:**

- по ТМЦ на складе был остаток 0;
- была проведена операция прихода на 10 единиц;
- приёмка завершена, если для прихода включена приёмка.

**Когда:** пользователь открывает экран остатков по складу.

**Тогда:** количество равно 10.

---

## BAL-DATA-005: Остаток после расхода

**Дано:**

- на складе было 10 единиц;
- проведён расход на 3 единицы.

**Когда:** пользователь открывает остатки.

**Тогда:** количество равно 7.

---

## BAL-DATA-006: Остаток после перемещения

**Дано:**

- склад А имел 10 единиц;
- склад Б имел 0 единиц;
- проведено перемещение 4 единиц со склада А на склад Б;
- приёмка завершена.

**Когда:** пользователь смотрит остатки по складам.

**Тогда:** остатки соответствуют доменному правилу перемещения.

Варианты доменного правила:

- склад А списывается на submit, склад Б получает после приёмки;
- оба склада меняются после приёмки;
- имущество переходит через состояние «в пути».

Перед финальным автотестом это правило нужно закрепить. Иначе тест будет не тестом, а гаданием на остатках, что, кстати, слишком похоже на реальную инвентаризацию.

---

## BAL-DATA-007: Остаток после списания

**Дано:**

- на складе было 5 единиц;
- проведено списание 2 единиц.

**Когда:** пользователь открывает остатки.

**Тогда:** количество равно 3.

---

## BAL-DATA-008: Остаток после выдачи

**Дано:**

- на складе было 5 единиц;
- проведена выдача 2 единиц на объект.

**Когда:** пользователь открывает остатки склада.

**Тогда:** складской остаток уменьшился до 3.

Выданное имущество должно отображаться не в остатках склада, а в «Репозитории выдачи».

---

## BAL-DATA-009: Остаток после возврата выдачи

**Дано:**

- за объектом числится 2 единицы ТМЦ;
- проведён возврат 1 единицы на склад.

**Когда:** пользователь открывает остатки склада.

**Тогда:** складской остаток увеличился на 1.

---

## BAL-DATA-010: Остаток после корректировки

**Дано:**

- фактический остаток отличается от системного;
- создана и подтверждена операция корректировки.

**Когда:** пользователь открывает остатки.

**Тогда:** количество соответствует результату корректировки.

Важно:

- старые операции не переписываются;
- изменение видно через историю операций;
- корректировка является отдельным бизнес-событием.

---

# 8. Сценарии сводки

## BAL-SUMMARY-001: Пользователь открывает сводку

**Дано:** пользователь находится на экране «Остатки».

**Когда:** нажимает кнопку «Сводка».

**Тогда:** открывается сводная информация по остаткам.

Сводка может показывать:

- количество доступных складов;
- количество ТМЦ с положительным остатком;
- количество нулевых остатков;
- общую статистику по складам;
- проблемные позиции;
- дату последнего обновления.

Точный состав сводки должен соответствовать API и текущей реализации.

---

## BAL-SUMMARY-002: Сводка учитывает права пользователя

**Дано:** пользователь имеет доступ не ко всем складам.

**Когда:** открывает сводку.

**Тогда:** сводка строится только по доступным данным.

Root и главный кладовщик могут видеть глобальную сводку.

---

## BAL-SUMMARY-003: Сводка открывается после фильтрации

**Дано:** пользователь выбрал склад и включил фильтр «Только положительные».

**Когда:** нажимает «Сводка».

**Тогда:** нужно определить правило:

- сводка по всем доступным остаткам;
- или сводка по текущим фильтрам.

Рекомендуемое правило:

```text
Сводка учитывает текущие фильтры экрана.
```

Если будет выбрано другое правило, UI должен явно показать это пользователю.

---

# 9. Сценарии пагинации и сортировки

## BAL-TABLE-001: Выбор количества строк на странице

**Дано:** список остатков открыт.

**Когда:** пользователь выбирает 10, 20 или 50 строк на странице.

**Тогда:** таблица показывает выбранное количество строк.

---

## BAL-TABLE-002: Переход между страницами

**Дано:** строк больше, чем помещается на одну страницу.

**Когда:** пользователь нажимает следующую страницу.

**Тогда:** отображается следующая порция остатков.

---

## BAL-TABLE-003: Сортировка по ТМЦ

**Дано:** в таблице несколько ТМЦ.

**Когда:** пользователь нажимает заголовок «ТМЦ».

**Тогда:** таблица сортируется по названию ТМЦ.

---

## BAL-TABLE-004: Сортировка по складу

**Дано:** отображаются остатки по нескольким складам.

**Когда:** пользователь нажимает заголовок «Склад».

**Тогда:** таблица сортируется по названию склада.

---

## BAL-TABLE-005: Сортировка по количеству

**Дано:** в таблице есть разные количества.

**Когда:** пользователь нажимает заголовок «Количество».

**Тогда:** таблица сортируется по количеству.

Проверка важна: количество должно сортироваться как число, а не как строка. Иначе `100` внезапно окажется меньше `9`, и где-то тихо заплачет кладовщик.

---

## BAL-TABLE-006: Сортировка по дате обновления

**Дано:** остатки обновлялись в разное время.

**Когда:** пользователь нажимает заголовок «Обновлено».

**Тогда:** таблица сортируется по дате.

Рекомендуемая сортировка по умолчанию:

```text
последние обновлённые сверху
```

или

```text
по названию ТМЦ внутри выбранного склада
```

Правило нужно закрепить.

---

# 10. Сценарии прав доступа

## BAL-PERM-001: Root видит все склады

**Дано:** в системе есть несколько складов.

**Когда:** root открывает экран остатков.

**Тогда:** он может выбрать любой склад и видеть остатки по всем складам.

---

## BAL-PERM-002: Главный кладовщик видит все склады

**Дано:** есть несколько складов.

**Когда:** главный кладовщик открывает экран остатков.

**Тогда:** он видит остатки всех складов.

---

## BAL-PERM-003: Кладовщик видит доступные остатки

**Дано:** кладовщик привязан к одному или нескольким складам.

**Когда:** открывает экран остатков.

**Тогда:** UI показывает остатки согласно доменной политике просмотра.

Нужно закрепить одно правило:

```text
Вариант А: кладовщик видит все остатки, но операции проводит только по своим складам.
Вариант Б: кладовщик видит только остатки своих складов.
```

Текущее UX-ожидание лучше зафиксировать явно, чтобы Playwright не тестировал старую версию прав.

---

## BAL-PERM-004: Observer видит остатки, но не выполняет действий

**Дано:** observer открыл экран остатков.

**Когда:** смотрит таблицу.

**Тогда:** он может искать, фильтровать и смотреть остатки.

Если на экране появятся быстрые действия вроде «создать расход» или «создать перемещение», observer не должен их видеть.

---

## BAL-PERM-005: Прямой запрос с недоступным складом

**Дано:** пользователь не имеет права видеть склад или действовать по складу.

**Когда:** он пытается открыть остатки через прямой запрос с site_id недоступного склада.

**Тогда:** сервер возвращает отказ или пустой результат согласно доменной политике доступа.

UI должен показать понятное сообщение, а не падать.

# 11. Негативные и странные сценарии

## BAL-EDGE-001: SyncServer недоступен

**Дано:** пользователь открывает экран «Остатки».

**Когда:** SyncServer недоступен.

**Тогда:** UI показывает ошибку:

```text
Сервер склада временно недоступен. Попробуйте позже.
```

Таблица не должна показывать старые данные как свежие без явной отметки.

---

## BAL-EDGE-002: Фильтр применён во время обновления остатков

**Дано:** пользователь применяет фильтр, а в это время проводится операция.

**Когда:** таблица обновляется.

**Тогда:** пользователь видит согласованное состояние, подтверждённое сервером.

Рекомендуемое правило:

```text
Экран показывает результат последнего успешного запроса.
```

---

## BAL-EDGE-003: Несуществующий ID ТМЦ

**Дано:** пользователь вводит ID, которого нет.

**Когда:** нажимает «Применить».

**Тогда:** отображается пустое состояние, а не ошибка сервера.

---

## BAL-EDGE-004: Слишком длинный поисковый запрос

**Дано:** пользователь вставил слишком длинный текст в поиск.

**Когда:** нажимает «Применить».

**Тогда:** UI либо ограничивает длину, либо сервер возвращает понятную ошибку.

Рекомендуемый текст:

```text
Слишком длинный поисковый запрос.
```

---

## BAL-EDGE-005: Быстрое многократное нажатие «Применить»

**Дано:** пользователь несколько раз нажимает «Применить».

**Тогда:**

- UI не создаёт гонку запросов;
- отображается результат последнего запроса;
- кнопка может временно блокироваться на время загрузки.

---

## BAL-EDGE-006: Неверный формат данных от сервера

**Дано:** сервер вернул некорректное количество или пустое название ТМЦ.

**Когда:** UI строит таблицу.

**Тогда:** экран не падает, а показывает безопасное состояние.

Рекомендуемо:

- пустое название показывать как «Без названия»;
- некорректное количество показывать как ошибку данных;
- логировать проблему.

---

## BAL-EDGE-007: Отрицательный остаток

**Дано:** сервер вернул отрицательный остаток.

**Когда:** пользователь открывает таблицу.

**Тогда:** UI должен явно показать проблему.

Рекомендуемый текст или отметка:

```text
Ошибка остатка: количество меньше нуля.
```

Отрицательный остаток не должен выглядеть как обычное рабочее значение.

# 14. Что нужно уточнить перед финальной реализацией

Перед превращением документа в строгие автотесты нужно закрепить несколько доменных правил:

1. Кладовщик видит все остатки или только остатки своих складов.
2. Какой формат даты использовать в колонке «Обновлено»: ISO или человекочитаемый.
3. Должны ли нулевые остатки показываться по умолчанию.
4. Что делать с отрицательными остатками: запрещать полностью или показывать как ошибку данных.
5. Должна ли кнопка «Сводка» учитывать текущие фильтры.
6. Нужен ли переход из строки остатка в историю операций по этой ТМЦ.
7. Нужны ли быстрые действия из остатков: «создать расход», «создать перемещение», «создать списание».
8. Как отображать единицы измерения в таблице: рядом с количеством или отдельной колонкой.
9. Должны ли временные ТМЦ отображаться в общем экране остатков или отдельным фильтром.
10. Как показывать имущество «в пути» при перемещениях, если будет введено такое состояние.

# 15. Краткая инструкция для пользователя

Экран «Остатки» показывает, сколько ТМЦ сейчас числится на складах.

Чтобы найти нужную ТМЦ:

1. Откройте раздел «Остатки».
2. Введите название, SKU или категорию в поле поиска.
3. При необходимости укажите ID ТМЦ.
4. Выберите склад.
5. Если нужны только позиции в наличии, включите «Только положительные».
6. Нажмите «Применить».
7. Найдите нужную строку в таблице.

В таблице:

- «ТМЦ» — название имущества или материала;
- «Склад» — где оно числится;
- «Количество» — сколько сейчас есть;
- «Обновлено» — когда остаток последний раз изменился.

Если количество равно `0`, значит ТМЦ заведена в системе, но на выбранном складе сейчас отсутствует.

Если количество выглядит неверным, его нельзя исправлять прямо в таблице. Нужно создать складскую операцию или корректировку.
